# Plan Check

[Live research workspace](https://plan-check-london.yummybuttercup2.chatgpt.site/) · [Original 3D explorer](https://plan-check-london.yummybuttercup2.chatgpt.site/model/)

An interactive research workspace about converting existing three-storey London houses into self-contained flats. One sidebar sheet is visible at a time. Filters persist between sheets; changing data release resets filters.

Run `python3 -m http.server 8095 --bind 127.0.0.1 --directory dist`.

## Data releases (never merged)

### Supplied conversion extract (default)

`dist/conversions-data.json` is prepared directly from the user's supplied CSVs with `scripts/build-supplied-data.py /path/to/data`. It contains 6,396 text-screened applications with recorded start dates 2019-01-01 to 2026-10-30, 4,175 category/evidence labels across 1,283 refusals, size features, and 1,020 matched resubmission pairs across 844 sites. Exact input SHA-256 hashes are in the JSON and in the Data & sources sheet. Exact query/extraction timestamp and query/classification scripts were not supplied. Files supplied 2026-11-07.

Local audit: all conversion IDs join to the supplied 66,880-row raw candidate extract. All classification IDs and both application IDs in every resubmission pair join to the conversion register. The raw extract (~135 MB), structured address columns, UPRNs and 1,173 deconversion records are not deployed. Site keys in the displayed matched-pair data are hashed for grouping only. Original supplied files are unchanged.

Outcomes map the supplied cleaned decision values: approved→Permitted, refused→Rejected, withdrawn→Withdrawn, pending/unknown→Undecided, other→Other. Original decision wording is retained.

Reasons use supplied rule classifications and excerpts, not classifications newly generated by this app. Coverage is 1,283/2,584 refusals; labels overlap. Source READMEs describe the upstream methods and their stated limitations; their review claims are not independent verification by Plan Check.

Size measures are reported or derived. Existing house area divided by parsed flat count is a proxy, not each flat's measured area. Extractor shortfall flags use incomplete schedules and minimal bedroom-count assumptions; they do not establish compliance. The 798 source storey values of three are not all verified as existing three-storey buildings. No verified-storey, heritage or dwelling filters are exposed.

Resubmission filters apply to the refused side. Each pair is a later conversion at the matched site within four years; other application types and appeals are outside this table. Site matches and description-derived changes do not establish causation. Known pair P0826 has next_units=1 while its next description lists two flats; the UI flags this without silently correcting it. No net-homes or homes-blocked totals are calculated.

### Foundations keyword snapshot

`dist/data.json`: 5,377 broad keyword candidates from a downloaded Foundations CSV (243,926 rows, 27 columns, 154,035,440 bytes). Source: https://foreman.house-london.uk/ . Snapshot 2026-10-05. Candidate start dates 2021–2025. Keyword screen: flat/self-contained plus conversion/convert/subdiv/sub-div. The 2,005 house-wording cohort is another heuristic. False positives, reverse/commercial conversions, amendments and conditions remain possible.

Outcome status and wording can disagree. Waltham Forest has 15 approval-wording/status discrepancies among 77 candidates; P/R-based shares are not reliable actual borough refusal rates before reconciliation. The UI flags this. Reasons, sizes and resubmissions are not joined to this release.

## Other assets and interpretation

`dist/boroughs.json`: 33 borough SVG shapes from https://github.com/house-london/0-stalledlondon/blob/main/public/data/london-boroughs.json . Explicit authority aliases; OPDC is not assigned to polygons. Boundary vintage is not established. The independent Sky Fragment source model does not establish conversion feasibility or compliance.

Refused share = Rejected/(Permitted+Rejected), excluding all other outcomes. Map/ranking shares are suppressed below 20 P/R records. Timings require both recorded dates and a finite non-negative interval; they are not statutory breach assessments. Applications and permissions do not prove delivered homes. Neither release contains plan-verified three-storey conversions.

All filters update overview, charts and case records. Map/ranking omit authority for comparison; annual bars omit year; outcome chart omits outcome; elapsed-day histogram omits its time-range filter. All global filters apply to reasons and sizes. Heatmap omits authority, requires 20 classified refusals per authority. No data from Forest or PlanX is connected.

## Verification

Independent source checks: supplied 2,882 permitted + 2,584 rejected = 5,466 decided; reasons 1,283/2,584 with 868 living-standards labels; area proxy available for 3,202 decided applications; reported flat sizes/shortfall flags for 2,825 decided applications; next approvals 473/923 decided pairs, 844 distinct sites, median gap 90 days. Source release switching preserves separation (6,396 vs 5,377) and hides supplied-only analysis in Foundations. Waltham supplied has 56 rejected/65 decided versus the Foundations audit flag. Known P0826 warning checked. HTML nesting, unique IDs, JavaScript syntax and data joins checked. Browser interactions and responsive sizing checked before publication.

## Screen-sized interface

The research canvas uses compact summary cards, a filter dialog and per-sheet subview tabs. Reasons splits into Categories / Evidence / Boroughs; sizes into Area bands / Extractor flag / Interpretation; retries into Overview / Compare pair / Refusal text; records into Proposal / Verification / Reasons / Register; sources into Release / Coverage / Files / Next steps / Map & model. Decisions and evidence questions have focused subviews as well.

Rankings, excerpts, reason lists and tables use Previous/Next controls sized to the available height. The heatmap shows one dropdown-selected reason at a time. Map height adapts to the current release's warning/notes. Full proposals, decision text, matching details and source explanations remain accessible in a detail dialog. Long documents may scroll in that explicitly opened dialog; main research sheets do not require page scrolling.

Browser fit checks: all main sheets at 1280×720 and 390×667 have canvas scrollHeight equal to clientHeight. Secondary tabs checked at 390×667, including corrected size bands, record verification, comparison cards and a warning pair (P0826). Foundations map and release inventory fit; the Files subview no longer carries the supplied manifest into the Foundations release. Filter dialog, previous/next paging, full-text opening and closing, evidence-to-record navigation and data-release separation checked. No source data or statistics changed in this interface update.

## Yomara’s original Sky Fragment explorer

The Building model sheet now embeds Yomara’s original BIMPLANING viewer from `BIMPLANING.zip`, with the detailed building shell and all 20 GLB levels. Standalone English: `dist/model/index.html`; Spanish: `dist/model/es/index.html`. Exterior orbit and hotspots, facade-by-use, stacked uses, individual levels, 3D / plan cuts and element details come from the supplied viewer. It loads on the first model-sheet visit.

The original HTML and README are preserved under `sources/yomara/`, with SHA-256 and byte manifests for every supplied file. Model regeneration scripts are under `model-tools/`; the Rhino source file is not included. Served pages adapt panel density when embedded and use vendored Three.js 0.183.0 modules (license included), avoiding runtime CDN dependencies. System fonts replace remote web fonts.

The source README declares metres and square metres. These are author-declared model units, not a survey validation. The 20 level entries include mezzanine and roof; space markers are not a verified self-contained dwelling count. No London planning application identity, existing/proposed conversion comparison or daylight assessment is supplied. The planning records and statistics remain unchanged; no case is promoted to plan-verified.

The earlier polygon-only `dist/sky-fragment.json` remains for traceability but is no longer the rendered model. The source archive is retained locally outside the repository; unmodified original pages and a file manifest allow the viewer adaptations to be reviewed.
